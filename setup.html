TWITCH INTERACTION MACHINE — ENTRY

Integrates this machine with your Twitch developer account. Each step is idempotent: revisit this page any time; done steps stay done. The machine itself is machine.html (same origin, shares this browser's storage).

1. ACCOUNTS read

  1. Bot identity = whichever Twitch account you log in with at step 4. If the bot should speak under its own name, create that account first and be logged in as it (in this browser) before step 4.
  2. Developer console requires two-factor authentication on the account that owns the application: open twitch.tv/settings/security (Settings → Security and Privacy) and enable 2FA under Security. The app owner and the bot account may be the same or different accounts.

2. REGISTER THE APPLICATION  

Open dev.twitch.tv/console/apps/create and fill the form:

  1. Name: must be unique across all of Twitch. Suggestion: …
  2. OAuth Redirect URLs: paste the redirect URL from step 0, then press Add.
  3. Category: Chat Bot.
  4. Client Type: Public. (Cannot be changed after creation. Public clients have no client secret and use the implicit grant, which is what a browser-only page can do. A confidential client also works, but its secret would be useless here.)
  5. Press Create, then Manage, and copy the Client ID. Client IDs are public by design; the secret (if any) is never used or stored by this machine.

4. AUTHORIZE (IMPLICIT GRANT)  

Sends you to Twitch to approve scopes user:read:chat (receive chat) and user:write:chat (send chat) for the account you are logged in as. Twitch returns the token in the URL fragment; this page stores it in this browser's storage and removes it from the address bar. The token is never written to history.

6. STREAMER PERMISSION  

FOUNDATION: the bot interacts "under explicit permission from the streamer." Observing public chat is passive; the machine will not enable the send capability until this record exists. Reading chat needs nothing from the streamer; sending as a non-moderator is subject to the channel's own chat rules (followers-only, slow mode, bans) and Twitch reports drops in RESULT.

7. PRE-FLIGHT  

  • Page served over https (Twitch rejects non-https redirect URLs except localhost)
  • Client ID saved
  • Token present and valid (id.twitch.tv/oauth2/validate)
  • Token carries user:read:chat and user:write:chat
  • Token was issued to this exact redirect URL
  • Target channel resolved to a broadcaster id
  • Streamer permission recorded (required for send; not for observe)
